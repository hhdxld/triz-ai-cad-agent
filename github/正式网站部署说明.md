# 登录网站与长期托管

## 当前可用功能

`hosted_app.py` 是新主入口。未登录只显示登录/注册页，登录后进入 CAD 工作台。闲置 30 分钟后，下次操作要求重新登录。账户切换、退出和超时会清除当前会话模型。

管理员入口为 `网站地址/?page=admin`。后台从数据库重新验证管理员角色，普通用户改网址无法取得管理员权限。管理员可修改单次报价和每日请求限额，查看用户数量、成功/失败/处理中订单，导出全站 CSV。真实到账指标在支付未接入时恒为零。

本机双击 `启动登录网站.cmd` 打开 http://127.0.0.1:8503。管理员通过 `设置管理员.cmd` 创建，没有默认管理员密码；原有本机管理员和用户使用同一个数据库，可以继续登录。

收费目前仍为演示：成功生成扣演示额度，失败退回；新账号获赠演示额度。真实支付、商户到账、退款、自动对账、找回密码邮件和支付回调未实现。不能把演示模式作为正式收款发布。

## 已准备的云端配置

- `Dockerfile` 使用 Python 3.12 和 CadQuery 所需系统库。
- `render.yaml` 配置单实例托管、10 GB 持久化盘、健康检查及 CI 成功后自动部署。示例选择付费 `1c-2g` 规格，创建前必须在平台确认费用；尚未创建或扣费。
- `cloud_server.py` 启动登录网站，异常退出由云平台重启。数据库及 STEP/STL 放持久化盘，而不是容器临时层。
- `site_backup.py` 使用 SQLite 在线备份，避免直接拷贝正在写入的数据库。启动时检查一次，之后每 6 小时备份，保留最近 14 份，并校验备份完整性。

本机功能与备份已测试；本机没有 Docker，Linux 容器构建还需要在云平台或 CI 实际验证。现有免费体验链接仍指向原来的免登录公开入口，未替换成这个登录站点。

## 托管步骤

1. 将源码与隐藏的 `.github`、`.streamlit` 配置一并上传到仓库根目录；不要上传 `.venv`、`outputs`、`.local-tools`、`.env` 或真实 `secrets.toml`。如果仍放在仓库的 `github/` 子目录，需要在 Render 指定该 Root Directory，并把工作流放到仓库根 `.github/workflows/`。
2. 登录 Render，连接 GitHub 仓库，使用 Blueprint 读取 `render.yaml`。创建服务时检查资源费用、磁盘、所选地区和 CI 设置。示例未绑定域名，部署成功后先使用平台实际分配的 HTTPS 地址。
3. 检查构建、健康检查、日志与 WebSocket 页面加载。必须实际完成登录、生成模型、STEP 下载和服务重启后的账本保留测试，再宣布公网登录版上线。
4. 在云平台 Shell 中执行 `python manage_business.py init-admin` 创建云端管理员；密码在交互终端输入，不放到代码、聊天或日志。本机数据库不会自动迁移到云端。
5. 若启用在线模型，将 API 设置仅放在云平台的环境变量。演示账号默认不允许消耗真实 API，保持 `AICAD_ALLOW_DEMO_API=false`。

Render 官方说明：[Blueprint 字段](https://render.com/docs/blueprint-spec)、[持久化磁盘](https://render.com/docs/disks)。托管磁盘不能直接多实例共享 SQLite；增加并发前需要 PostgreSQL、任务队列和对象存储。

## 真实收费接入还需要的资料

先确定微信支付、支付宝或其他实际可用的支付平台，并提供已开通的商户类型，不要发送商户私钥或密码。依据所选平台实现创建支付订单、签名校验、金额/币种/商户/订单核对、重复通知幂等处理、查单与退款。

资金账本必须与当前演示账本分离，新用户不能获得可花费的真实赠款。支付成功必须以服务端验证结果为准，不能用浏览器“已付款”或个人收款二维码解锁。为按次收费，应明确“付款后生成”和“生成失败退款”的规则，并在真实环境进行小额端到端测试。

当前 `AICAD_BILLING_MODE=live` 会明确报错并停止提供服务，防止未接入支付时假装正式收费。仅修改环境变量不会完成支付功能。

## 备份与维护

自动备份位于 `/var/data/backups`，包含密码哈希和订单，不能上传公开仓库或开放下载。同盘备份不包括模型文件，也不能防止磁盘整体损坏；正式运营还需要设置受保护的异地备份、磁盘容量告警和备份失败告警。

恢复时先暂停服务，选择通过完整性检查的副本，备份当前账本，再替换 `/var/data/business.sqlite` 后启动。若使用 WAL，应在服务完全停止后同步处理对应 WAL/SHM，不要在运行中覆盖数据库。

目前中断的建模订单会保留“处理中”，不能贸然按时间判定失败并退款。真实收费上线前需增加持久化任务状态、重启恢复及退款对账，避免人工猜测资金状态。

云托管减少重启、部署和备份操作，但仍需管理商户结算、成本、客户问题及告警。当前源码已准备部署，尚无已验证的永久公网地址或真实收款能力。
