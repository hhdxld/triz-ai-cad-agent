# AI CAD Agent 第一版设计草案

日期：2026-10-04。状态：供用户审阅，尚未开始实现。

## 1. 产品目标与已确认需求

开发独立应用，帮助用户通过自然语言生成和修改三维机械零件。用户已经确认：独立应用、三维机械零件、在线模型 API。

Agent 应实现需求解析、TRIZ 结构分析、参数化 CAD 生成、设计检查以及持续修改。用户最初规定的十二个栏目用于完整设计报告，不强制每次尺寸修改都生成整篇报告。

## 2. 第一版推荐范围

以 Windows 本地应用为目标，提供桌面窗口、中文界面、聊天区、三维预览、参数面板与项目历史。模型推理通过用户配置的 API 完成，几何运算与文件保存均在本机进行。

优先验证安装板、支架、外壳和轴套。第一版支持单零件，以及外壳与盖板这类少量静态零件组成的结构；复杂装配、自由曲面、运动仿真和有限元分析作为后续扩展。

默认单位为 mm。用户提供值、推荐值和待确认项分别记录。关键尺寸缺失时先澄清；允许采用工程推荐值时明确展示来源类别，不把推荐值写成用户输入。

## 3. 技术路线比较

1. CadQuery：推荐第一版采用。通过 Python 构建参数化实体，导出 STEP、STL；项目自身保存参数与建模步骤。
2. FreeCAD：适合对原生 CAD 文档及特征树有要求的版本，后续通过独立适配器接入。
3. 双引擎：增加集成与验证成本，第一版采用单引擎、预留接口。

依据：
- https://cadquery.readthedocs.io/en/latest/index.html
- https://github.com/CadQuery/cadquery/blob/master/doc/importexport.rst
- https://www.freecad.org/features.php

STEP 是几何交换文件，不承诺保留完整参数与特征历史。应用内参数化项目及生成的 Python 源文件承担持续编辑功能。

## 4. 应用架构

界面使用本地 Web 界面与桌面窗口封装，提供交互式三维预览。Python 本地服务承担项目存储、Agent 编排、API 适配、建模执行及检查。界面通过本地接口访问服务；服务只监听回环地址。

各模块职责：

| 模块 | 输入 | 输出与职责 |
| --- | --- | --- |
| 需求解析 | 对话、已有项目 | 结构化需求、已确认参数、推荐参数、关键缺失项 |
| TRIZ 分析 | 功能目标、制造条件、矛盾 | 至少三种候选结构、评分、推荐及理由 |
| 建模规划 | 需求、选定方案、当前特征 | 参数关系、结构化建模操作、参数变更 |
| CAD 执行器 | 经校验的建模操作 | 实体、预览网格、STEP、STL、Python 源文件 |
| 设计检查 | 参数、实体、制造约束 | 分级问题、检查证据、可执行修复建议 |
| 项目管理 | 对话、参数、特征、版本 | 本地项目文件、版本记录、恢复上一版 |
| API 适配 | 用户配置、消息、输出约束 | 模型响应、用量、超时与错误信息 |

第一版采用可配置的兼容聊天补全协议的模型 API：用户填写 API 基础地址、模型名称、密钥，并可测试连接。供应商不硬编码；不同协议通过适配器扩展。界面默认隐藏密钥，日志和项目文件不记录密钥明文。

## 5. Agent 工作闭环

用户描述 → 解析需求 → 补充关键参数 → 生成设计或执行尺寸修改 → 校验参数与操作 → 本地建模 → 检查实体 → 更新预览 → 保存版本 → 导出。

模型通过工具请求结构化操作，由程序执行。支持的第一批操作包括草图基本轮廓、拉伸、旋转、布尔运算、孔、槽、圆角、倒角、抽壳、阵列与零件定位。允许的参数、操作数量和执行时间由执行器控制。模型输出不直接作为任意 Python 程序执行。

CAD 执行器失败时把操作标识和错误摘要交回 Agent，最多自动修复两次。仍失败则展示原因并保留上一个有效版本。界面不能把失败任务显示为已生成模型。

TRIZ 采用按需模式：直接指定形状和尺寸时建模；用户提出结构创新或矛盾优化时生成至少三种可加工候选方案。方案按功能、创新性、加工、成本、可靠性、维护、安全及建模难度评分，展示权重与评分理由。成本评分属于定性估计，不伪装成供应商报价。

## 6. 参数化与连续修改

项目存储原始需求、参数值、来源类别、单位、参数表达式、特征及其稳定标识、对话、版本和检查结果。

参数变更通过依赖关系计算。例如修改长度时，按约定保持端部孔边距或孔间距；约定未明确且会影响功能时询问用户。修改外壳长度不能顺带改变壁厚。保留零件与特征标识，在已有设计上更新。

每次修改先生成候选版本，建模和必要检查成功后才成为当前版本。用户能够比较版本并恢复历史版本。重新打开项目后仍可继续对话修改。

## 7. 检查与结果表达

自动检查实体是否有效、体积是否为正、尺寸是否符合目标、参数关系是否成立。孔边距、壁厚、运动间隙、传感器视野等检查仅在对应结构及约束存在时运行。

多零件结构根据定义的配合关系检查非预期体积重叠，区分接触、预期配合与干涉。制造建议结合用户选择的 3D 打印、CNC 或板材方式；未选择方式时不声称制造检查已通过。

强度、安全、材料性能及工艺能力没有可靠输入或计算支持时标记为未验证。几何检查不等同于强度验证。

完整设计报告按用户指定顺序包含：用户需求理解、TRIZ 问题分析、关键技术矛盾、发明原理选择、三种创新结构方案、最优方案、CAD 尺寸参数表、零件清单、CAD 建模步骤、CAD 代码、可制造性检查、后续优化建议。直接建模任务不适用的章节明确注明，不虚构矛盾或候选方案。

## 8. 错误处理与数据保存

API 连接失败、鉴权失败、超时或输出格式不合格时提供可操作的错误信息。对话与已有项目继续保留；重试不会覆盖有效模型。

建模在独立工作进程执行，设置超时与资源边界。API 调用发送需求及必要项目摘要；未经任务需要不发送本地任意文件。项目保存采用先写候选文件再替换的方式，防止中断损坏。

## 9. 验收标准

1. 用户配置实际 API 后，可通过自然语言生成真实 CAD 实体；演示数据不能冒充模型调用结果。
2. 输入“创建 100 × 60 × 5 mm 的安装板，四个直径 6 mm 的通孔，孔中心距相邻边 10 mm”，生成正确实体和预览。
3. 输入“长度改为 140 mm，保持孔边距”，长度与相关孔位更新，宽度、厚度和孔径保持原值。
4. 非法尺寸和无法执行的圆角等操作有明确失败信息，上一有效版本可恢复。
5. 导出的 STEP、STL 可由独立读取工具检查，实体尺寸符合输入；导出的 Python 源文件可重新生成对应模型。
6. 保存并重新打开项目后，参数、特征、历史和后续修改能力仍可用。
7. TRIZ 任务提供至少三种方案和有解释的评分，推荐方案能够转成受支持的建模操作。
8. 没有 API 密钥时显示配置引导，不宣称 AI 生成功能已验证。

## 10. 实施顺序

先实现项目数据与 CAD 执行器，再接入 API 和 Agent 工具调用，随后完成对话、预览、参数修改与导出，最后加入 TRIZ 报告和针对典型零件的设计检查。以完整闭环验收，而非仅交付界面原型。
